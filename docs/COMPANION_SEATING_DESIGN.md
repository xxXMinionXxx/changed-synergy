# 胶兽伙伴乘坐方案

状态：已实现并完成独立 Forge 服务端与客户端验证。实际操作见[伙伴乘坐说明](COMPANION_SEATING.md)。首批范围为原版船、矿车、Changed 座椅，以及以 Superb Warfare 为首个适配对象的模组载具。沿用现有关系／功能轮盘，不增加独立管理界面。

## 玩家操作

| 场景 | 轮盘选项 | 结果 |
| --- | --- | --- |
| 与有指挥权限的朋友或羁绊互动 | 指定座位 | 关闭轮盘，进入这只胶兽的座位选择状态。 |
| 玩家已坐在支持的多座载具中 | 召集乘坐 | 玩家自身关系轮盘的结伴行动位置显示此选项，招呼附近正在跟随自己的胶兽登上同一载具的空位。单只胶兽的轮盘仍可指定它上车。 |
| 胶兽正在前往座位 | 取消乘坐 | 取消这条命令，恢复此前的跟随或等待状态。 |
| 胶兽已经乘坐 | 下座 | 在安全条件下离开座位，恢复此前状态。 |

“指定座位”支持准星选实体载具，也支持点选已适配的座椅方块。底部显示“为〈胶兽名〉选择座位：右键确认，Esc 取消”；提示使用玩家当前绑定的交互键，不写死鼠标按键。选择开始前已经按住的键不算确认，选择状态最多持续十五秒。

能读取空位时，准星目标显示物体名称和可用座位数；通用适配无法读取容量时只显示“尝试加入”，不编造空位数量。不支持、已满或被占用时给出能确定的原因，不能确定时提示“目标未允许该胶兽乘坐”。右键只提交座位选择，消费这次操作，避免同时让玩家上车、开箱或使用手持物品。无效目标保持选择状态，允许继续选；Esc、再次使用指定命令、打开其他界面或超时退出选择。

“召集乘坐”只召集十六格内、当前确实跟随该玩家且能接受命令的胶兽，包括跟随中的营地随行队。正在营地工作、等待、战斗、救援、包裹或被擒抱的胶兽不被拉走。座位少于伙伴数时，按距上车点由近到远分配，距离相同按 UUID 排序；其余保持原状态。用一条汇总反馈报告“已安排 2 只上车，1 只因座位已满继续跟随”，不逐只刷聊天。

## 上下座与任务优先级

胶兽正常走到座位／车体旁的可达上车点，再调用原座位的乘坐逻辑。大型载具按车体边缘或适配器提供的入口选点，不要求胶兽走进实体中心。船边允许能安全游泳的胶兽靠近登船；不会强迫水生胶兽上岸，也不让陆生胶兽为登船进入深水。

不添加追赶传送，不瞬移进车，不把其他乘客挤下来。原版座位使用普通 `startRiding`，保留 Forge 乘坐事件和载具本身的拒绝条件。载具快速移动、已经起飞或没有可达入口时，提示停稳后再上车。体型是否可容纳由座位适配检查决定，不能用强制乘坐绕过限制。

座位命令只临时占用移动和视线控制，不改变羁绊、好感、营地分工、货物或原有跟随开关。上车过程中暂停普通跟随寻路；上车后也不能让跟随目标立即把胶兽拉下来。新命令、战斗或救援可以取消尚未完成的上车任务。完成乘坐后，普通社交、游荡和工作目标不得重新抢占移动。

手动“指定座位”相当于让胶兽坐在那里，玩家离开不会自动召回。“召集乘坐”上车的伙伴在玩家下车后尝试安全下车并恢复跟随；如果仍在高空、危险液体上方或找不到安全落脚点，则继续乘坐并提示原因，不强制抛出乘客。车辆自身的脱离、损坏和逃生规则仍有效；本功能不赋予胶兽自动驾驶或操作车载武器的能力。

## 座位识别与 Superb Warfare

| 类型 | 识别和分配方式 |
| --- | --- |
| 原版普通船 | 使用实际载客上限和已有乘客，保留现有乘客次序。 |
| 原版运输船（箱船） | 只有一个乘客位；箱子不是第二个座位，玩家坐上后不能召集。 |
| 原版可乘坐矿车 | 只允许一个乘客；不把漏斗、箱子、熔炉等功能矿车当普通座位。 |
| Changed 椅子／枕头 | 复用现有 `SeatEntity`、座椅方块实体和占用状态；不生成重叠的座位实体。 |
| Superb Warfare | 使用其有编号的座位表，读取真实空位并通过它自己的接口完成座位分配。 |
| 其他模组座位 | 提供基于原版乘客机制的通用接入；不要求每个模组单独登记容量。无法读取座位编号时按顺序尝试正常乘坐，是否接纳该胶兽由目标自身决定。独立座位实体、仅限玩家或有特殊授权流程的模组仍需专门适配。 |
| 模组增加的双人马等坐骑 | 玩家已经正常骑上的驯服坐骑也可进入通用“召集乘坐”流程，尝试加入后排；不改变坐骑归属、操控和驯服状态，也不模拟玩家去触发驯服／打开物品栏等右键行为。 |

已核查 Superb Warfare **1.20.1 的 `0.8.9.1-1.20` 分支**，参考提交 `993063bed60ac4d0a8d75ca9972765f4557172c8`：

- `VehicleEntity.getOrderedPassengers()` 保留空座位的 `null` 占位；普通 `getPassengers()` 已过滤空位，因此不能用乘客列表下标当座位号。
- 容量来自 `computed().seats()`／`getMaxPassengers()`；`getSeatIndex(entity)` 返回实体当前座位号。
- 普通登车先填第一个空位；要指定其他空位，需要登车后调用 `changeSeat(entity, index)` 并检查返回值和最终座位。每一步仍由服务端核验，失败时只回退本次新上车的胶兽，不能下掉原有乘客。
- 其 `interact` 允许玩家替换非玩家驾驶员。因此胶兽默认优先乘客位，召集时不填驾驶位；手动指定空载车辆也优先非驾驶位。只有单座载具才使用唯一座位，并明确提示它不会开车。
- 不复用管理员 `/superbwarfare ride` 的强制乘坐／换人分支，也不直接写它的座位 NBT 或乘客列表。适配通过可选依赖桥接完成，未安装或接口不匹配时停用这一适配，不影响船和矿车。

已使用 Superb Warfare `0.8.9.1-hotfix` 的实际发布包，在独立 Forge 服务端验证 M1A2 和快艇的编号座位、乘客登乘、驾驶位保留与锁定拒绝。其他版本、单座载具及附属载具尚未逐一实测，其权限和专用要求仍以所装版本为准。

### 未专门适配模组的通用接入

优先使用专门适配；没有适配时，玩家已经乘坐的对象可尝试通用“召集乘坐”。未知对象的手动指定须由整合包通过实体类型允许标签登记，避免把任意生物、玩家代理或擒抱实体当座椅。

通用层保留目标动态覆盖的 `canAddPassenger` 和正常 `startRiding(target, false)` 检查，包括 Forge 乘坐事件。不会写死马只能坐一个，也不会把未知载具写死为两座。原模组若正常接纳非玩家实体，胶兽就可以尝试加入；若拒绝，则停止这次尝试并说明原因，不用强制乘坐绕过。

未知容量的载具采用逐只登乘队列，不能提前承诺座位数或虚构座位编号。每次登乘前重新检查目标和现有乘客，交由原模组选择实际空位，成功后再处理下一只；每只的尝试次数和等待时间均有上限。玩家抢先占座时尊重实际结果，不换掉乘客，不持续重试。此队列只防止本功能的并发冲突，不声称能预留其他模组内部的座位。

作为源码示例，已查看 [Two Players One Horse 的马类注入](https://github.com/Beethoven92/TwoPlayersOneHorse/blob/6f5b8499c8ae58f1abd4ad19ae827e7def252cfb/common/src/main/java/com/beethoven92/twoplayersonehorse/mixin/TwoPlayersOneHorseAbstractHorseMixin.java)：该实现直接放宽 `canAddPassenger(Entity)` 的人数限制，未在这项检查中限定 `Player`，属于适合通用接入的实现方式。这只是对该源码版本的判断，尚未验证其 Forge 1.20.1 发布版与胶兽的实际乘坐效果。

通用接入只争取基本登乘、保持乘坐和下座；不能保证任意模组的姿势、座位偏移、隐藏乘客、镜头或武器槽位都正确。有的模组虽然能坐两名玩家，却在其他环节强制转换为玩家类型，这类仍需检查或专门适配。

## 服务端状态与中断处理

流程：选择目标 → 校验并预留空位（未知座位使用登乘队列）→ 靠近上车点 → 再次校验并上车 → 保持乘坐；任一步都可以取消。服务器为每只胶兽至多保留一条座位命令，已知座位的预留键包含维度、载具 UUID 和座位号；座椅方块则使用维度和方块位置。预留不阻止真人正常上车，玩家占用后取消胶兽的该次预留，并反馈座位已被占用。

客户端只发送选择和取消意图。服务器重新检查操作者、胶兽身份、现有指挥权限、视线、距离、目标类型和空位。不允许通过伪造包支配陌生胶兽、其他玩家的伙伴或远处／未加载的载具。TrueTransfur 原生玩家使用实际可交互身体来判断视线和所乘载具，不能把代理身体或四足胶兽当成普通座位目标。

上车任务的寻路沿用 `CreatureTaskNavigation` 的失败退避和进展检查，并定期更新上车点。任务最多二十秒；持续无进展提前退出，不反复向不可达车体寻路，也不加载远处区块。胶兽死亡、变形、断线、区块卸载、目标销毁或玩家取消时，释放预留和导航；变形不转移未完成的乘坐命令。

活动中的选座和空位预留不存档。已完成的正常乘客关系由原模组存档；额外只记录指令归属和“手动指定／召集”来源，以便重载后恢复正确的下车／跟随行为。加载时核对实际乘坐对象，不匹配就清掉指令状态，不复活旧预留或凭记录重新拉上车。

## 配置与验收

提供默认开启的 `CompanionSeating`（手动指定座位）与 `CompanionRallyBoarding`（批量召集）两个独立开关。关闭后禁止新增对应命令，取消未完成的上车任务；已经坐好的乘客仍可安全下车。补齐中、英、俄文提示，图标沿用现有轮盘绘制与居中方式。

实际实施时至少覆盖：

- 普通船两座、箱船一座、矿车空／满座，船边和轨道旁安全上下车。
- Superb Warfare 两座、多座和单座载具；驾驶位留空、乘客位不连续、玩家换座，以及同系附属载具。
- 通用接入覆盖允许非玩家乘客的双人马、未知容量载具、拒绝 NPC 的座位、玩家抢先登乘和多只伙伴排队，不虚报容量或绕过权限。
- 两名玩家同时召集、玩家抢先占座、人数超过容量，确保不会换掉现有乘客或让两只胶兽占同一座位。
- 普通朋友、羁绊、随行队、幼崽、四足、水生及飞行体型；无权限、工作／战斗／救援中的对象不响应。
- 已上车时普通跟随不会立刻下车；新命令可以取消上车，玩家下车后召集来的伙伴安全恢复跟随。
- 车辆开走、不可达入口、危险下车点、死亡／变形／卸载／重载，以及可选模组缺失或接口变化。
- 确认选择状态消费一次输入，Esc 不误开菜单，失败只提示一次；大量伙伴时搜索、预留和寻路有界。
